Textbook Chapter · pi-delegate

Keeping Parent Instructions Out of Delegate Workers

A subagent can receive global instructions through two independent routes; reliable isolation closes both routes while preserving the project context it actually needs.

01 / 05

Background & Foundational Landscape

Mental model

Pi is a host process that can own several AgentSession objects. The parent session is interactive; a delegated worker is a separate session with its own model loop, tools, resource loader, and system prompt. That system prompt is not one immutable string: Pi compiles it from a base prompt plus discovered resources such as context files and skills.

Prerequisites

  • AGENTS.md is instruction text injected into a model's system prompt; it is not executable sandboxing.
  • cwd means the task's working directory, while agentDir is Pi's global configuration directory, normally ~/.pi/agent.
  • A prompt can be inherited as text even when the child ResourceLoader never discovers the original file.

Context

The original behavior had two doors. First, Pi's ResourceLoader discovered the global file at ~/.pi/agent/AGENTS.md; on this machine that path and ~/.agents/AGENTS.md point to the same target. Second, ad-hoc delegation copied the parent's already-assembled system prompt, which already contained its <project_context> section. Filtering only the loader would leave the inherited copy intact.

02 / 05

Intuition Before Details

The core trick

Treat context isolation as a two-door problem: remove global files at the child ResourceLoader seam, and remove the parent's compiled context section before copying the parent prompt.

High-level goal

Think of the parent as a courier carrying a folder into a clean office. The worker should receive the task's project folder and the base operating instructions—not the courier's private household rulebook. Checking only the office's filing cabinet is insufficient if the courier already carried a photocopy through the door.

Expected outcome

A worker launched in the repository still sees the repository's AGENTS.md. A worker launched elsewhere sees that task directory's context. In neither case does a user-global AGENTS.md silently become part of the worker's instructions.

The Micro-World (Interactive Playground)

Disable either protection and watch the same global instruction leak through the remaining route. Project context is intentionally kept on the board.

04 / 05

Literate Structural Breakdown

The diff is small because it changes two seams rather than teaching every caller about isolation. First make the resource list safe; then make prompt inheritance safe; finally pin both behaviors with tests.

1. Name the context candidates

Pi can choose several conventional filenames for one directory. The filter treats all of those context candidates as global when they sit directly under a global root. The set is deliberately about context filenames, not every Markdown file: custom agent definitions in ~/.agents/ are a separate feature. 

const CONTEXT_FILE_NAMES = new Set([
  "AGENTS.override.md", "AGENTS.md", "AGENTS.MD",
  "CLAUDE.md", "CLAUDE.MD",
]);

This separates “a file Pi may inject as ambient context” from “a Markdown file that happens to exist.” That distinction matters because the legacy .agents directory also stores named agents.

2. Match discovered paths, not symlink targets

The machine that exposed the bug uses symlinks. The ResourceLoader reports the path it discovered, such as /home/daniel/.pi/agent/AGENTS.md, while the file's canonical target may live somewhere else. Therefore this policy compares resolved lexical paths against two roots: the configured Pi agentDir and the legacy ~/.agents directory. 

function isExcludedGlobalContextFile(filePath: string, agentDir: string): boolean {
  const discovered = resolve(filePath);
  const roots = [resolve(agentDir), resolve(homedir(), ".agents")];
  return roots.some((root) => {
    const relativePath = relative(root, discovered);
    return CONTEXT_FILE_NAMES.has(relativePath);
  });
}

The important subtlety is the word discovered. Canonicalizing the candidate would turn a symlink into its target and could make a perfectly ordinary path look unrelated to the root that Pi scanned.

3. Filter at the ResourceLoader seam

The child still gets its task-specific project context. Only the final list returned by Pi's loader is filtered, so the policy is local and does not mutate the parent session or globally alter Pi's resource discovery. 

agentsFilesOverride: ({ agentsFiles }) => ({
  agentsFiles: agentsFiles.filter(({ path: contextPath }) =>
    !isExcludedGlobalContextFile(contextPath, agentDir),
  ),
}),

This is a deep seam: callers continue to ask the ResourceLoader for context files, while the host-dependency builder enforces the subagent policy once for every fresh loader. It also applies to explicit or named child prompts, where parent inheritance is not the only source of context.

4. Remove the second route: inherited parent context

A full ctx.getSystemPrompt() is already compiled. Passing it verbatim to the child would smuggle the parent's context section around the loader filter. The resolver removes Pi's structured section first; the child then rebuilds context for its own cwd. 

const parentSystemPrompt = stripInheritedProjectContext(
  ctx.getSystemPrompt?.(),
);

The helper preserves the base prompt and text outside <project_context>. It is intentionally not a string replacement for one known global path: every inherited context file is stale from the child's point of view, and the child loader is the authoritative place to add the right project context back.

5. Tests prove the two doors independently

The host test creates a symlinked global context file and a real project file, then asserts that only the project file reaches the ResourceLoader. The lifecycle test puts a global marker inside a fake parent prompt and asserts that the model-facing child prompt does not contain it. One test catches loader regressions; the other catches prompt-inheritance regressions. 

expect(files.map(({ content }) => content)).toEqual([projectContext]);
expect(files.map(({ content }) => content)).not.toContain(globalContext);

expect(capturedSystemPrompt).not.toContain(globalInstruction);

The final runtime check showed only the repository's AGENTS.md in the child's discovered context. The full suite passed with 512 tests, which is useful evidence that isolation did not remove task-scoped project guidance.
